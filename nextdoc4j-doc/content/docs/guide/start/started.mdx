title: 快速开始
description: 在已有 Spring Boot Web 项目中，添加依赖、启用配置并打开 NextDoc4j；按需展开 BOM、WebFlux 和网关接入示例。
---

在一个可以启动的 **Spring Boot Web 项目**中，完成下面三步即可打开文档工作台。需要 **JDK 17+、Maven 3.9+**；新项目请先准备对应的 Web Starter。

## 1. 添加依赖

选择宿主的 Boot 主版本。以下以 **WebMVC** 为例；已有 SpringDoc UI 时，检查并复用其兼容版本，避免重复声明。

<Tabs items={['Spring Boot 3', 'Spring Boot 4']}>
  <Tab value="Spring Boot 3">

```xml title="pom.xml · Boot 3.5.x + SpringDoc 2.x"
<dependency>
    <groupId>top.nextdoc4j</groupId>
    <artifactId>nextdoc4j-spring-boot-starter</artifactId>
    <version>1.5.0</version>
</dependency>
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.9.1</version>
</dependency>
```

  </Tab>
  <Tab value="Spring Boot 4">

```xml title="pom.xml · Boot 4.x + SpringDoc 3.x"
<dependency>
    <groupId>top.nextdoc4j</groupId>
    <artifactId>nextdoc4j-spring-boot-starter</artifactId>
    <version>1.5.0</version>
</dependency>
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>3.1.1</version>
</dependency>
```

  </Tab>
</Tabs>

**WebFlux 项目**将 `springdoc-openapi-starter-webmvc-ui` 换成 `springdoc-openapi-starter-webflux-ui`，NextDoc4j Starter 坐标保持不变。请按宿主实际 Web 栈二选一。

## 2. 启用配置

```yaml title="application.yml"
nextdoc4j:
  enabled: true
```

`enabled` 默认是 `false`。使用 Properties 时，写为 `nextdoc4j.enabled=true`。

## 3. 启动并访问

打开 **`http://localhost:8080/doc.html`**，端口替换为宿主应用的实际端口。设置了 `server.servlet.context-path` 或 WebFlux 基础路径时，在文档地址前加上相应前缀。

看到工作台后，展开“接口文档”，选择接口并进入“在线调试”。`/v3/api-docs` 应能返回 OpenAPI JSON；没有业务接口时，可以先添加下面的示例。

## 按需展开

<details>
<summary>使用 BOM 统一管理依赖版本</summary>

示例取自仓库 Demo 的版本组合。已有 `spring-boot-starter-parent` 或 Boot BOM 时，复用现有平台管理；不要再导入第二套 Boot 版本。

| 宿主 | `spring-boot.version` | `springdoc.version` |
| --- | --- | --- |
| Spring Boot 3 | `3.5.16` | `2.9.1` |
| Spring Boot 4 | `4.1.1` | `3.1.1` |

在现有 `pom.xml` 中合并下面的版本管理片段。选择 Boot 4 时，同时替换前两项版本属性：

```xml title="pom.xml · 三个 BOM"
<properties>
    <spring-boot.version>3.5.16</spring-boot.version>
    <springdoc.version>2.9.1</springdoc.version>
    <nextdoc4j.version>1.5.0</nextdoc4j.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>${spring-boot.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>org.springdoc</groupId>
            <artifactId>springdoc-openapi-bom</artifactId>
            <version>${springdoc.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>top.nextdoc4j</groupId>
            <artifactId>nextdoc4j-bom</artifactId>
            <version>${nextdoc4j.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

随后可以移除第一步两个依赖中的 `<version>`。NextDoc4j BOM **只对齐自身模块**，SpringDoc 也不由 Boot BOM 自动管理。

</details>

<details>
<summary>添加第一个接口：根据 ID 查询用户</summary>

把下面的 Controller 放在 Spring Boot 启动类能够扫描到的包中。示例包含 DTO 定义和完整导入，无需额外引入枚举、安全等插件。

```java title="UserController.java"
package com.example.demo;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/user")
@Tag(name = "用户管理", description = "用户查询示例")
public class UserController {

    @GetMapping("/{id}")
    @Operation(summary = "根据 ID 查询用户")
    public UserView getUserById(
            @Parameter(description = "用户 ID", example = "1")
            @PathVariable("id") Long id) {
        return new UserView(id, "NextDoc4j User");
    }

    @Schema(description = "用户信息")
    public record UserView(
            @Schema(description = "用户 ID", example = "1") Long id,
            @Schema(description = "用户名", example = "NextDoc4j User") String name) {
    }
}
```

刷新文档后，在“用户管理”下打开“根据 ID 查询用户”，填写 `id=1` 并发送请求：

```json title="GET /api/user/1 · 预期响应"
{
  "id": 1,
  "name": "NextDoc4j User"
}
```

  alt="仓库 Demo 中根据 ID 查询用户的接口详情"

标准 `@Tag`、`@Operation`、`@Parameter` 和 `@Schema` 会直接用于文档展示，不需要 NextDoc4j 专用接口注解。

</details>

<details>
<summary>接入 Spring Cloud Gateway 聚合文档</summary>

网关改用 `nextdoc4j-gateway-spring-boot-starter`，并自行引入匹配的 Spring Cloud Gateway、SpringDoc UI 和 Spring Cloud BOM。**网关 Starter 已依赖单体 Starter，无需再重复声明单体 Starter。**

下面依赖片段使用前面的 BOM 管理 NextDoc4j 与 SpringDoc 版本；Gateway 版本由宿主的 Spring Cloud BOM 管理。仓库 Boot 3 / Boot 4 Demo 分别使用 Cloud `2025.0.3` / `2025.1.2`。

```xml title="pom.xml · Gateway WebFlux"
<dependency>
    <groupId>top.nextdoc4j</groupId>
    <artifactId>nextdoc4j-gateway-spring-boot-starter</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway-server-webflux</artifactId>
</dependency>
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webflux-ui</artifactId>
</dependency>
```

WebMVC 网关将后两个依赖分别换为 `spring-cloud-starter-gateway-server-webmvc`、`springdoc-openapi-starter-webmvc-ui`。

配置 `nextdoc4j.enabled=true`，保证网关路由能够转发下游 `/v3/api-docs`。下游服务只需提供有效的 SpringDoc OpenAPI；需要下游自带 NextDoc4j 页面或插件时，再按需引入对应模块。多分组读取、路由前缀和手动服务配置见[网关聚合插件](/guide/plugin/gateway)。

</details>

## 常见问题速查

| 现象 | 先检查什么 |
| --- | --- |
| `/doc.html` 返回 404 | `nextdoc4j.enabled=true`；`production` 未开启；端口、上下文路径及自定义 `doc-path` 正确 |
| 页面打开但接口文档加载失败 | `/v3/api-docs` 能否返回 JSON；SpringDoc UI 与当前 Web 栈匹配；宿主安全过滤器是否放行文档资源 |
| 启动时出现缺类、方法不存在 | Boot 3 对应 SpringDoc 2.x，Boot 4 对应 3.x；检查重复或冲突的 SpringDoc / Jackson 依赖 |
| 网关列表为空或服务不可用 | 路由是否存在有效 Path 规则；下游服务是否启动；网关转发后的文档 URL 是否能直接访问；复杂规则可先手动配置文档地址 |
| 字段显示为 `arg0` 或对象参数未展开 | 编译时启用 `-parameters`；按需开启 `springdoc.default-flat-param-object=true` |

更多排查方式见[完整 FAQ](/more/faq)。
