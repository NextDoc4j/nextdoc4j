**NextDoc4j 是面向 Spring Boot 的 OpenAPI 3 文档增强方案，基于 SpringDoc，为应用提供可替代 Swagger UI 的文档与在线调试界面。**

引入 Starter、启用配置，就能在应用内打开文档工作台。接口定义继续使用标准 OpenAPI 注解，已有的 SpringDoc 分组和模型描述可以沿用。

## 项目定位

NextDoc4j 连接已有的 Spring Boot 接口与开发者的日常调试流程：

- **接口信息更集中**：从服务、SpringDoc 分组和标签定位接口，在同一工作区查看参数、模型、示例和附加 Markdown 文档。
- **调试上下文可延续**：多标签切换接口，保存参数草稿，统一管理认证、请求头和查询参数，减少重复填写。
- **文档访问可控制**：按配置开启文档登录、关闭文档资源，或通过生产模式屏蔽文档入口。
- **多服务入口可统一**：在 Spring Cloud Gateway 中发现服务文档，处理外部访问路径和认证信息，按服务切换工作区。

SpringDoc 负责生成 OpenAPI；NextDoc4j 负责扩展文档信息、提供界面和调试能力。接入时，宿主项目需要显式引入与 Web 栈匹配的 SpringDoc UI 依赖。

## 核心能力

| 能力 | 在工作台中可以做什么 |
| --- | --- |
| 文档阅读 | 查看接口分组、请求与响应字段、模型、JSON 示例和 Markdown 文档；通过全局搜索定位接口 |
| 在线调试 | 编辑路径、查询参数、请求头、Cookie、JSON/XML 请求体、表单和上传文件；生成 cURL |
| 请求流程 | 使用请求前后操作、变量提取、接口串联和 JavaScript 脚本处理调试数据 |
| 响应查看 | 阅读结构化 JSON、XML 和文本；接收 SSE 事件；下载文件响应 |
| 工作区 | 使用多标签、固定标签、深浅主题和按应用、服务隔离的浏览器状态 |
| 文档导出 | 选择接口导出 OpenAPI JSON、Markdown、HTML、Word；通过浏览器打印另存 PDF |
| 文档保护 | 配置密码登录、文档开关、自定义入口和生产模式 |
| 品牌与插件 | 定制标题、Logo、页脚；扩展枚举说明、安全元数据、Sa-Token 权限角色及网关聚合 |

<Callout title="文档保护与接口鉴权" type="info">
文档登录保护文档资源的访问；接口上的 Token、角色和权限仍由宿主应用的认证框架校验。NextDoc4j 可以展示安全要求并为调试请求携带凭据。
</Callout>

## 适用场景

| 场景 | 接入方式 | 适合的项目 |
| --- | --- | --- |
| 单体 WebMVC | `nextdoc4j-spring-boot-starter` + SpringDoc WebMVC UI | 使用 Servlet、Spring MVC Controller 的业务应用 |
| 单体 WebFlux | 同一个单体 Starter + SpringDoc WebFlux UI | 使用响应式 Web 栈的应用 |
| Gateway WebFlux | `nextdoc4j-gateway-spring-boot-starter` + 对应 Gateway 和 SpringDoc UI | 基于响应式网关聚合多个服务文档 |
| Gateway WebMVC | 同一个网关 Starter + 对应 Gateway 和 SpringDoc UI | 基于 Servlet 网关聚合多个服务文档 |

Starter 坐标在 Boot 3 / Boot 4 间保持一致。Web 栈、Boot、Spring Cloud 和 SpringDoc 版本由宿主项目选择与管理，详见[快速开始](/guide/start/started)和[网关聚合](/guide/plugin/gateway)。

## 与 Swagger UI 如何选择

两者都以 OpenAPI 为基础。下面比较的是各自常见的默认接入方式；Swagger UI 也可以通过配置、插件和宿主服务扩展。

| 维度 | Swagger UI | NextDoc4j |
| --- | --- | --- |
| 接口规范 | 展示 OpenAPI 文档 | 沿用 OpenAPI，结合 `x-nextdoc4j-*` 扩展增强展示 |
| 文档阅读 | 以接口列表与展开详情为主 | 提供工作区、多标签、模型页、搜索和 Markdown 导航 |
| 在线请求 | 内置 Try it out 和认证输入 | 在调试页整合参数草稿、全局参数、请求前后操作和控制台 |
| SSE 调试 | 展示能力取决于集成与版本 | 提供流式事件列表与持续接收状态 |
| 文档访问保护 | 通常交由宿主应用或反向代理配置 | 提供可选的文档密码登录和生产模式开关 |
| 品牌定制 | 可通过配置或自定义构建实现 | 通过配置传递标题、Logo 与 Markdown 页脚 |
| 多服务文档 | 可以配置多个文档地址 | 提供 Gateway 路由发现、文档地址处理和按服务隔离的工作区 |
| 导出 | 可获取 OpenAPI 源文档 | 支持接口子集与多种阅读格式导出 |

如果你希望继续使用 SpringDoc 的接口描述，同时需要更完整的文档阅读、调试与网关聚合流程，可以从 NextDoc4j 的单体 Demo 开始体验。

## 版本与兼容性

当前项目版本为 **1.5.0**，Java 基线为 **17**。仓库 Demo 使用以下版本组合：

| 技术栈 | Spring Boot | SpringDoc | Spring Cloud（网关场景） |
| --- | --- | --- | --- |
| Boot 3 | `3.5.16` | `2.9.1`（2.x） | `2025.0.3` |
| Boot 4 | `4.1.1` | `3.1.1`（3.x） | `2025.1.2` |

Boot 3 搭配 SpringDoc 2.x，Boot 4 搭配 SpringDoc 3.x。跨版本迁移时应同时检查宿主依赖树与对应 SpringDoc / Spring Cloud 的兼容要求。NextDoc4j BOM 只管理自身模块版本，不替宿主管理这些平台依赖。
