工作台里的“全局认证”负责给业务接口准备凭据，“全局参数”负责复用公共请求字段。接口详情中的权限信息用于解释调用要求，实际权限校验仍由后端执行。

## 先区分三个层次

| 层次 | 解决什么问题 | 配置或操作入口 |
| --- | --- | --- |
| 文档访问密码 | 谁可以打开 NextDoc4j 文档 | [简单认证配置](/guide/config/authconfiguration) |
| 接口认证 | 调试某个业务接口时带哪个 Token / Key | 文档管理 → 全局认证 |
| 业务权限 | 当前账号是否满足角色、权限和业务条件 | 服务端鉴权；详情页展示声明的元数据 |

文档密码登录成功，不意味着调试接口时自动获得业务 Token。界面显示了某个权限码，也不意味着当前账号已经拥有该权限。

## 全局认证中心

页面根据 OpenAPI 的 `components.securitySchemes` 列出认证方案。左侧可以按已配置 / 待配置筛选或搜索，右侧查看注入目标、填写凭据、保存或清空，并对照原始方案声明。

### 填写内容与注入位置

| 方案 | 填写方式 | 注入位置 |
| --- | --- | --- |
| HTTP Bearer | Token，已含 `Bearer ` 前缀时不会重复添加 | `Authorization` Header |
| HTTP Basic | `用户名:密码`，或已有 `Basic ` 凭据 | `Authorization` Header，必要时按 UTF-8 编码后转 Base64 |
| API Key | Key 的实际值 | 按方案的 `in` 与 `name` 放到 Header、Query 或 Cookie |
| OAuth2 / OpenID Connect | 已取得的访问 Token | 当前凭据构造按 Bearer 写入 Authorization；这里不提供完整授权服务器登录流程 |

声明了方案还不够，接口需要通过 `security` 引用该方案，调试才知道这个接口需要什么。多个候选方案与同一组中的组合要求，也应按 OpenAPI 声明理解。

### 建议的操作顺序

1. 先打开目标接口，阅读认证方案名称和注入位置。
2. 到全局认证选择同名方案，填写并点击“保存凭据”。
3. 返回调试，在 Headers / Params 等位置确认来源与待发送值。
4. 请求失败时先查看实际请求与响应，不要只反复更换输入框中的值。

单体 Demo 展示 Bearer 方案。当前凭据默认保存在浏览器标签页会话范围，网关中还按服务区分；它不会自动同步给团队其他成员。清空凭据只移除本地配置，不会使服务端 Token 自动失效。

## Sa-Token 权限信息怎么看

接口头部可以展示 `@SaCheckPermission`、`@SaCheckRole` 与 `@SaIgnore` 等注解对应的元数据。示例中的新增用户展示权限组合，更新用户展示角色要求。

| 标记 | 含义 |
| --- | --- |
| 权限 / 角色列表 | 调用该接口声明需要的权限码或角色名 |
| AND | 组合条件需要同时满足 |
| OR | 候选条件中满足其一 |
| 额外角色条件 | 读取权限条件外允许的角色分支，按界面完整组合理解 |
| 匿名 / 忽略鉴权 | 对应元数据声明该接口不走相同认证要求 |

不能把所有徽章拼成一个没有逻辑关系的权限列表。联调遇到 403 时，要对照组合关系检查账号与后端配置，而不是仅确认某一个权限字符串存在。

后端注解如何透传见[Sa-Token 插件](/guide/plugin/satoken)；标准认证方案的声明见[认证展示插件](/guide/plugin/authentication)。

## 统一管理公共 Header 与 Query

“文档管理 → 全局参数”包含 Header 和 Query 两类。例如租户 ID、渠道标识或公共版本参数，可以配置一次，在多个接口中复用。

<ThemedScreenshot light="/images/screenshots/features/global-parameters-light.webp" dark="/images/screenshots/features/global-parameters-dark.webp" alt="全局参数中新增 X-Tenant-Id 请求头并填写演示值与说明" width={1100} height={310} />

| 字段 / 操作 | 用途 |
| --- | --- |
| 启用开关 | 控制该默认参数是否参与请求 |
| 参数名 | 真实 Header 或 Query 名称 |
| 参数值 | 后续调试使用的默认值 |
| 说明 | 记录字段用途，便于识别 |
| 底部新增行 | 填写后生成新的参数行，继续添加下一项 |
| 覆盖 / 删除 | 针对当前范围修改默认值或移除配置 |

普通公共字段放在这里；已有 SecurityScheme 的认证凭据优先在全局认证中配置，避免维护两份互相冲突的 Authorization。

## 参数来源与优先关系

调试页会合并公共参数、接口参数和认证值。理解以下规则比记住一张简单的“全局永远优先”表更有用：

- 公共配置提供默认值，接口明确填写的非空值可以覆盖同名默认值。
- 认证值在相应目标尚未获得有效值时补入；已明确填写的 Header 不会随意被 Token 替换。
- 当前调试的单次覆盖用于决定这次请求的值；显式禁用会排除该项。
- Header 按不区分大小写的名称匹配，Query 按名称匹配，同名多值 Query 按接口输入保留。

发生冲突时，查看调试行的来源与“实际请求”，不要仅根据全局配置页推断最终发送内容。

## 网关下的全局默认与服务覆盖

聚合模式的公共参数支持“网关全局默认”和“当前服务”范围。当前服务可以继承默认项，也可以覆盖同名项或加入服务自己的字段。

| 目标 | 推荐范围 |
| --- | --- |
| 所有服务共享同一个租户 Header | 网关全局默认 |
| 某服务使用不同租户或版本值 | 当前服务覆盖 |
| 仅一个服务需要的 Query | 当前服务新增 |
| 只想临时改一次请求 | 当前接口的调试覆盖 |

认证方案声明也有来源：服务自身的同名方案优先于网关级补充声明。方案定义合并与“凭据是否跨服务复用”不是一回事，切换服务后应重新确认当前认证配置。

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 认证页没有方案 | 检查当前 OpenAPI 的 securitySchemes 与所选服务 / 分组 |
| 保存 Token 后请求仍然没有认证头 | 检查接口是否引用该方案、是否声明匿名，以及该行是否被单次禁用 |
| 请求头中有另一个旧 Token | 检查同名公共参数、接口覆盖和当前服务范围 |
| Cookie 方案不生效 | 核对目标域登录、浏览器凭据选项、SameSite 与跨域策略 |
| 401 与 403 混淆 | 先看后端响应含义，分别检查身份凭据与角色权限 |
| 全局参数没影响别的微服务 | 确认修改的是网关默认，还是当前服务的独立配置 |
