如果每次联调都需要先取 Token、生成签名或保存返回 ID，可以把这些动作加入调试页的“前置操作”和“后置操作”。它们围绕当前请求执行，不需要改变后端业务接口。

## 什么时候用哪一个阶段

| 阶段 | 执行时机 | 常见任务 |
| --- | --- | --- |
| 前置操作 | 主请求发出之前 | 准备变量、补齐 Header、转换字段、先执行辅助请求 |
| 主请求 | 参数准备完成后 | 发送当前接口请求，生成实际请求快照 |
| 后置操作 | 收到主请求响应后 | 校验状态、提取数据、回填认证、保留后续联调需要的值 |

在对应页签点击“添加步骤”，选择操作类型。每个步骤可以单独启用或禁用，并配置条件、触发方式与失败策略。

## 八种操作分别解决什么问题

| 操作 | 作用 | 示例 |
| --- | --- | --- |
| 发送辅助请求 | 在流程内调用另一个接口 | 先读取公共配置或执行登录 |
| 提取并保存变量 | 从请求、响应或已有结果中取值 | 从响应中读取 `data.id` |
| 转换数据 | 文本、类型、编码、摘要与加密处理 | 去空白、Base64、SHA-256 |
| 设置请求参数 | 把值写入主请求对应位置 | 设置 Header、Path、Query 或 Body 字段 |
| 条件校验 | 检查相等、包含、非空等条件 | 检查响应状态或业务字段 |
| 回填认证 | 将提取到的值保存到指定认证方案 | 把登录返回的 Token 用于下一次请求 |
| JS 脚本 | 用代码组合更复杂的联调处理 | 根据多个字段计算或生成参数 |
| 填写变量后再发送 | 要求先补齐流程变量 | 手动准备验证码、确认号等值 |

“设置请求参数”和“填写变量后再发送”用于前置阶段；后置阶段不提供这两类直接准备主请求的步骤。需要为下一次请求准备值时，可以保存到流程变量或认证方案。

## 变量的两个范围

| 范围 | 生命周期 | 适合保存什么 |
| --- | --- | --- |
| 本次运行变量 | 当前一次执行过程 | 中间计算值、一次性的提取结果 |
| 流程变量 | 当前页面会话内，同一应用 / 服务范围共享 | 后续接口还需要的 ID、验证码或临时关联信息 |

“流程变量缓存”入口可以查看、填写和清理当前范围中的值及辅助步骤结果。**流程变量保存在内存中，刷新页面后清除**；它与调试草稿缓存的持久化规则不同。

网关服务之间使用不同范围，不应假定切换到另一个服务还能直接读取前一个服务的流程变量。

## 一个不依赖登录的最小流程

可以先在用户查询接口练习下面的配置：

1. 在 Params 中填写 `id=1`。
2. 在前置操作添加“设置请求参数”，来源选固定值，目标选 Header，字段填写 `X-Request-Source`，值填写 `nextdoc4j-demo`。
3. 在后置操作添加“条件校验”，检查响应状态等于 `200`。
4. 再添加“提取并保存变量”，从响应 JSON 取 `data.id`，保存为流程变量 `lastUserId`。
5. 点击发送，在“实际请求”核对请求头，在“控制台”查看步骤结果，并打开流程变量缓存确认数据。

JSON 字段路径支持按界面提供的候选项选择；具体填写形式以当前字段的提示为准。接口返回包装结构不同时，应改成实际的响应路径。

## 先登录，再调用业务接口

需要登录场景时，可以按“辅助请求 → 提取 Token → 回填认证”的顺序组织：

| 步骤 | 需要确认 |
| --- | --- |
| 辅助请求登录 | 请求方法、地址、Body 格式和登录参数 |
| 提取 Token | 真实返回结构中的字段路径，不能假定总是 `data.token` |
| 回填认证 | 选择业务接口真正引用的 SecurityScheme |
| 发送主请求 | 在实际请求中确认认证位置、前缀和值 |

辅助请求可以选择或填写接口，配置请求头、正文与是否继承请求头。跨域、Cookie、超时等仍受浏览器和目标服务限制。

需要验证码或人工输入时，可以先手动运行支持独立执行的辅助步骤，再补齐流程变量。不是所有步骤都支持手动运行：依赖改写主请求或阻止主请求的操作，需要随完整流程执行。

## 转换与签名处理

可视化转换包含文本处理、JSON 与类型转换、URL / Base64 编解码、MD5、SHA-256、AES-128-CBC 和 RSA 等选项。

选择算法之后，还要匹配后端约定的字符编码、密钥格式、IV、摘要大小写、输入字段顺序与输出编码。仅选择同名算法不代表与后端签名规则完全一致。

## JavaScript 示例

添加“JS 脚本”后，使用当前工作台提供的 `nextdoc` API。前置脚本可以读取与修改请求，后置脚本可以访问响应并保存流程数据。

<Tabs items={['前置脚本', '后置脚本']}>
  <Tab value="前置脚本">

```javascript
nextdoc.request.headers.set('X-Request-Source', 'nextdoc4j-demo');
nextdoc.variables.set('startedAt', Date.now());
console.log('请求头已准备');
```

  </Tab>
  <Tab value="后置脚本">

```javascript
nextdoc.assert(nextdoc.response.status === 200, 'HTTP 状态应为 200');
const user = nextdoc.response.json('data');
nextdoc.assert(Boolean(user && user.id), '响应应包含用户 ID');
nextdoc.flow.set('lastUserId', user.id);
console.log('已保存用户 ID');
```

  </Tab>
</Tabs>

| API 分类 | 常用能力 |
| --- | --- |
| `nextdoc.request` | 读取或设置 Body、Header、Query、Path、Form、Cookie |
| `nextdoc.response` | 读取状态、JSON 路径、文本与可用响应头 |
| `nextdoc.variables` | 本次运行变量的 get / set |
| `nextdoc.flow` | 流程变量的 get / set / remove |
| `nextdoc.security` | 向指定认证方案回填 Token |
| `nextdoc.crypto` | 摘要、编码和加密工具 |
| `nextdoc.sendRequest` | 发起辅助请求 |
| `nextdoc.assert` / `console` | 断言与记录运行信息 |

脚本通过独立 Worker 执行，不能按普通网页脚本使用 DOM。它提供的是 `nextdoc` API，不是 Postman 的 `pm` API；复制其他工具脚本后需要调整。

## 顺序、失败与控制台

步骤按配置顺序执行，可依据变量、流程数据或响应设置条件。失败策略决定“中止”还是“继续”，手动触发步骤与自动步骤也应分别确认。

前置操作对请求字段的改写用于本次实际发送，保留编辑区原来的草稿。要核对脚本或步骤是否生效，应查看“实际请求”，而不只看发送前的输入框。

控制台提供 ALL、PRE、NET、POST 筛选，适合先定位失败阶段，再查看错误、跳过与校验结果。若准备 Token 的步骤失败，却选择继续执行，主请求仍可能因为缺少凭据返回 401。

调试草稿可以保存步骤配置，但不会把内存中的流程变量永久保存。需要重新开始一次联调时，分别检查步骤配置、流程变量和全局认证值，避免混淆它们的生命周期。
