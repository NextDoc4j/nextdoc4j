枚举插件在 SpringDoc 生成文档时补充 `type`、`format`、`enum` 和 `x-nextdoc4j-enum`。工作台据此展示枚举含义，并为 JSON Body、Query 和表单等调试输入提供候选项。

它负责文档元数据；JSON 序列化、请求参数转换和业务校验仍由宿主工程配置。

## 最小接入

宿主需要先完成 [NextDoc4j 与 SpringDoc 接入](/guide/start/started)，再添加插件：

```xml title="pom.xml"
<dependency>
    <groupId>top.nextdoc4j</groupId>
    <artifactId>nextdoc4j-plugin-enum</artifactId>
    <version>1.5.0</version>
</dependency>
```

已导入 `nextdoc4j-bom` 时可省略版本。Boot 3 使用 SpringDoc 2.x，Boot 4 使用 SpringDoc 3.x；插件坐标相同。

<Tabs items={['YAML', 'Properties']}>
  <Tab value="YAML">

```yaml title="application.yml"
nextdoc4j:
  enabled: true
  plugin:
    enum:
      enabled: true
```

  </Tab>
  <Tab value="Properties">

```properties title="application.properties"
nextdoc4j.enabled=true
nextdoc4j.plugin.enum.enabled=true
```

  </Tab>
</Tabs>

| 配置 | 未配置时 | 作用 |
| --- | --- | --- |
| `nextdoc4j.enabled` | 工作台不开放 | 控制文档访问入口 |
| `nextdoc4j.plugin.enum.enabled` | 不装配枚举插件 | 注册枚举参数处理器与模型转换器 |

枚举插件不依赖 `nextdoc4j.extension.enabled`。普通 Java enum 可以继续由 SpringDoc 描述；内置增强解析器默认识别实现 `EnumValue` 的枚举。

## 基础用法：值与含义一起定义

下面以数字状态为例，不依赖 Lombok：

```java title="RoleStatus.java"
import com.fasterxml.jackson.annotation.JsonCreator;
import com.fasterxml.jackson.annotation.JsonValue;
import top.nextdoc4j.enums.core.EnumValue;

public enum RoleStatus implements EnumValue<Integer> {
    ACTIVE(1, "启用"),
    DISABLED(2, "停用");

    private final Integer value;
    private final String description;

    RoleStatus(Integer value, String description) {
        this.value = value;
        this.description = description;
    }

    @Override
    @JsonValue
    public Integer getValue() {
        return value;
    }

    @Override
    public String getDescription() {
        return description;
    }

    @JsonCreator
    public static RoleStatus fromValue(Integer value) {
        RoleStatus result = EnumValue.getByValue(value, RoleStatus.class);
        if (result == null) {
            throw new IllegalArgumentException("未知角色状态: " + value);
        }
        return result;
    }
}
```

`EnumValue<T>` 的泛型用于推导文档类型，`getValue()` 提供真实候选值，`getDescription()` 提供说明。不重写描述方法时，默认使用枚举常量名；所有说明都等于常量名时，内置解析器不额外写入含义扩展，但仍可生成标准枚举值。

### 在接口中使用

```java title="EnumDemoController.java"
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.media.Schema;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/enum-demo")
public class EnumDemoController {
    public record ChangeStatus(@Schema(description = "角色状态") RoleStatus status) {}

    @Operation(summary = "提交角色状态")
    @PostMapping
    public ChangeStatus submit(@RequestBody ChangeStatus request) {
        return request;
    }

    @Operation(summary = "按状态查询")
    @GetMapping
    public String query(@RequestParam RoleStatus status) {
        return status.getDescription();
    }
}
```

JSON 请求正文可以是 `{"status": 1}`，响应中的状态也序列化为数字。这里的 JSON 行为由 `@JsonCreator` / `@JsonValue` 决定，安装文档插件本身不会替你注册业务枚举的序列化器。

### Query、Path 和表单的数字转换

Spring 的 Query / Path / 表单绑定与 Jackson 处理 JSON 是两条链路。上面的数字状态若要接收 `?status=1`，需要注册转换器：

```java title="RoleStatusConverter.java"
import org.springframework.core.convert.converter.Converter;
import org.springframework.stereotype.Component;

@Component
public class RoleStatusConverter implements Converter<String, RoleStatus> {
    @Override
    public RoleStatus convert(String source) {
        return RoleStatus.fromValue(Integer.valueOf(source));
    }
}
```

默认按枚举常量名称绑定时，通常需要传 `ACTIVE` 等常量名。请让文档候选值、JSON 映射和 Spring 参数绑定约定保持一致；自定义 MVC / WebFlux 转换体系时，也要确认转换器进入了实际使用的 ConversionService。

## 自定义功能：适配已有枚举接口

团队已有 `getCode()` / `getLabel()` 约定时，可以保留现有枚举类型，通过 `EnumMetadataResolver` 适配：

```java title="BusinessEnum.java"
public interface BusinessEnum<T> {
    T getCode();
    String getLabel();
}
```

```java title="BusinessEnumResolver.java"
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import top.nextdoc4j.enums.resolver.EnumMetadataResolver;

@Component
@Order(50)
public class BusinessEnumResolver implements EnumMetadataResolver {
    @Override
    public boolean supports(Class<?> enumClass) {
        return enumClass != null && enumClass.isEnum()
            && BusinessEnum.class.isAssignableFrom(enumClass);
    }

    @Override
    public Class<?> getEnumInterfaceType() {
        return BusinessEnum.class;
    }

    @Override
    public String getValueMethodName() {
        return "getCode";
    }

    @Override
    public String getDescriptionMethodName() {
        return "getLabel";
    }
}
```

例如枚举直接实现 `BusinessEnum<String>` 时，默认逻辑会提取该接口泛型，再调用公开的 `getCode()`、`getLabel()`。该适配同样只作用于文档，保留宿主原有的 JSON 和参数转换配置。

### 哪些方法可以重写

| 方法 | 用途 | 返回默认值时 |
| --- | --- | --- |
| `supports` | 限定支持的枚举类型 | 必须实现 |
| `getEnumInterfaceType` | 指定用于提取泛型的接口 | `null` 使用 `EnumValue` |
| `getValueMethodName` | 指定值方法 | 默认 `getValue` |
| `getDescriptionMethodName` | 指定说明方法 | 默认 `getDescription` |
| `resolveValueType` | 直接决定 Schema 类型 | `null` 按接口泛型推导 |
| `resolveFormat` | 直接决定 Schema 格式 | `null` 走默认推导 |
| `resolveEnumValues` | 自定义标准候选值列表 | `null` 反射读取各常量的值 |
| `resolveMetadata` | 自定义值与说明映射 | `null` 使用默认元数据构造 |

复杂继承、泛型无法直接提取或特殊值类型，建议显式重写类型、格式与值解析。例如长整数规范应使用 `type=integer`、`format=int64`；不要仅根据 Java 类型名拼出 Schema 类型。

元数据可以用 `new NextDoc4jEnumMetadata(List.of(new NextDoc4jEnumMetadata.EnumItem(value, description)))` 构造，相关类型位于 `top.nextdoc4j.enums.model`。需要主动不输出说明扩展时，可以返回 items 为空的元数据对象；返回 `null` 的含义是回退默认解析。

### 多个解析器如何选择

Spring 收集解析器 Bean，插件按注入顺序查找，**第一个 `supports=true` 的解析器生效**，并在该解析器内部对未重写的方法执行回退。可用 `@Order` 控制自定义 Bean 顺序。

没有自定义解析器支持时，才尝试内置 `EnumValue` 解析器。避免写一个支持所有 enum 的解析器，却没有实现这些类型实际使用的方法。

## 验证生成的数据

在当前服务 `/v3/api-docs` 的对应参数或模型 Schema 中检查：

```json title="RoleStatus 的 Schema 片段"
{
  "type": "integer",
  "format": "int32",
  "enum": [1, 2],
  "x-nextdoc4j-enum": {
    "items": [
      { "value": 1, "description": "启用" },
      { "value": 2, "description": "停用" }
    ]
  }
}
```

先确认标准 `enum` 的值和类型，再检查说明扩展。只有修改了一段文字描述，没有结构化枚举信息时，前端不会据此推断完整选择器。

## 排查速查

| 现象 | 优先检查 |
| --- | --- |
| 引入后没有增强 | 插件开关、当前 OpenAPI 分组、枚举字段是否进入模型 |
| 有候选值但没有业务说明 | 是否实现 / 适配枚举接口，说明是否全部等于常量名 |
| 数字枚举显示成字符串 | 接口泛型能否直接提取，或显式重写类型与格式 |
| Query 下拉选数字后返回 400 | Spring 参数转换器，而不只是 Jackson 注解 |
| JSON 候选值与真实返回不同 | 宿主序列化器、`@JsonValue` 和解析器返回值是否一致 |
| 自定义解析器没有执行 | Bean 扫描范围、`supports` 条件与 `@Order` |
| 获取值或说明失败 | 方法必须可被反射调用，且说明返回 String |
